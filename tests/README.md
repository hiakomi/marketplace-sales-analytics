# Проверки retention на синтетических данных

Тесты запускают SQL из `sql/customers/` на PostgreSQL-движке PGlite в памяти. Они не используют API, рабочую базу, сетевые реквизиты или реальные клиентские данные. Node.js нужен только для этого локального инструмента проверки, а не для загрузчиков проекта.

## Запуск

Нужен Node.js 20 или новее. Из корня репозитория:

```bash
npm ci --prefix tests
npm test --prefix tests
```

Версия зависимости зафиксирована в `package-lock.json`. Установка требует доступа к npm; сами тесты работают локально. Зависимость и `node_modules` не входят в Python-окружение приложения.

## Что проверяется

- Месяц без активности остаётся в результатах с нулём; будущие месяцы исключены.
- Взвешенный retention включает размер неактивной, но подходящей когорты в знаменатель.
- Фиксированные январские–июньские когорты сохраняют один знаменатель во всех точках M0–M6.
- Несколько строк продажи в один день не увеличивают число активных клиентов, но входят в выручку.
- Фильтры периода и `quantity > 0` исключают неподходящие строки.
- При отсутствии активных клиентов выручка на исходного клиента равна нулю, а на активного — `NULL` (показатель не определён).
- Пустая база и отсутствие подходящих ранних когорт обрабатываются без выдуманных наблюдений.
- Знаменатель и накопленные суммы согласованы с существующим запросом фиксированного LTV.

## Контрольный пример

В [фикстуре](fixtures/retention.sql) два январских клиента, один февральский и один июньский. Начальная выручка — 540, исходная численность — 4. В M1 активен только июньский клиент с выручкой 30: retention фиксированного набора равен **25%**, а не 100%. В M3 нет активности ни у одной ранней когорты: все четыре клиента остаются в знаменателе, retention равен 0%.

Для общей взвешенной кривой в M1 также подходит июльский клиент, а декабрьский ещё не имеет полного месяца. Получаем **1 / 5 = 20%**. Эти ожидаемые значения заданы вручную, независимо от реализации запроса.

Проверки подтверждают логику на малом наборе. Они не подтверждают производительность на VPS и не пересчитывают исторические агрегаты из `data/summary/`.
