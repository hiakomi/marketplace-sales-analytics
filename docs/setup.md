# Запуск загрузчиков

## Окружение

Установите зависимости из `requirements.txt` в виртуальное окружение. Версии библиотек пока не закреплены: исходный файл не содержал версий, а окружение VPS не предоставлено. Список не является lock-файлом.

Оба скрипта требуют переменных `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`. При отсутствии обязательной переменной выполнение завершится до обращения к API. `DB_PORT` по умолчанию равен 5432.

### Linux / macOS

Скопируйте `.env.example` в `.env` и заполните локальными значениями. Для следующих команд файл должен содержать доверенные присваивания в синтаксисе shell; значения со специальными символами заключайте в одинарные кавычки.

```bash
cp .env.example .env
# Отредактируйте .env, затем загрузите переменные в текущий процесс:
set -a
source ./.env
set +a
python daily_load.py
```

`source` исполняет shell-файл, поэтому здесь используется только ваша локальная конфигурация.

### Windows PowerShell

```powershell
$env:DB_HOST = 'localhost'
$env:DB_PORT = '5432'
$env:DB_NAME = 'marketplace'
$env:DB_USER = 'analyst'
$secureDbPassword = Read-Host 'Пароль PostgreSQL' -AsSecureString
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $secureDbPassword).Password
python daily_load.py
Remove-Item Env:DB_PASSWORD
```

Чтобы запустить историческую загрузку, замените последнюю команду запуска на `python load.py`. Переменные действуют для текущей сессии и её дочерних процессов; планировщику необходимо настроить окружение отдельно.

## Требования к PostgreSQL

Загрузчики сами не создают базу или пользователя. Перед первым запуском создайте таблицу командой из [`sql/00_create_sales.sql`](../sql/00_create_sales.sql). Таблица `sales` должна быть доступна через `search_path` и содержать следующие поля.

| Поле | Приведение в загрузчике |
|---|---|
| `client_id` | Python `int` |
| `gender` | Значение из API |
| `purchase_datetime` | Python `date`; для клиентских SQL требуется столбец PostgreSQL `date` |
| `purchase_time_as_seconds_from_midnight` | Python `int` |
| `product_id` | Python `int` |
| `quantity` | Python `int` |
| `price_per_item` | Python `int` |
| `discount_per_item` | Python `int` |
| `total_price` | Python `float` |

Учётной записи загрузчика нужны права подключения, доступа к схеме, `DELETE` и `INSERT` в `sales`. Для исследования нужны права `SELECT`.

## Историческая загрузка

`load.py` перебирает даты с 01.01.2023 по 31.12.2023 включительно. Таймаут HTTP-запроса — 30 секунд, размер пакета вставки — 1000 строк.

Ошибка отдельного дня выводится в консоль, после чего обработка продолжается. Финальная строка «Историческая загрузка завершена» и код завершения 0 **не гарантируют, что загрузились все дни**. Проверяйте журнал: сообщение «день не загружен» означает пропуск, который нужно повторно обработать. Автоматических повторов HTTP-запросов нет.

## Ежедневная загрузка

`daily_load.py` выбирает вчерашнюю календарную дату через `date.today()`. Часовой пояс определяется средой запуска; отдельного параметра даты пока нет. При ошибке скрипт пробрасывает исключение и завершается с ошибкой.

На VPS загрузка запускается ежедневно в 07:00 по системному времени сервера. Пример задания находится в [`deployment/cron.example`](../deployment/cron.example): оно переходит в каталог проекта, экспортирует переменные из локального `.env`, запускает Python из виртуального окружения и направляет стандартный вывод и ошибки в `daily_load.log`.

Добавить расписание можно командой:

```bash
crontab -e
```

Проверьте системный часовой пояс и последние записи журнала:

```bash
timedatectl
crontab -l
tail -n 50 /opt/marketplace_etl/daily_load.log
```

Файл `.env` и журнал не следует добавлять в Git.

## Замена дня и проверки

`DELETE` и `INSERT` фиксируются вместе, при исключении во время загрузки выполняется rollback. Пустой ответ API не удаляет старые строки. Скрипты не проверяют, что все даты строк ответа совпадают с запрошенной датой, и не блокируют параллельный запуск одной даты. Запускайте загрузчики последовательно; не назначайте два задания на одну выгрузку.

После загрузки проверьте доступный диапазон и количество записей:

```sql
SELECT MIN(purchase_datetime), MAX(purchase_datetime), COUNT(*)
FROM sales;

SELECT purchase_datetime, COUNT(*) AS rows_count
FROM sales
WHERE purchase_datetime >= '2023-01-01'
  AND purchase_datetime < '2024-01-01'
GROUP BY purchase_datetime
ORDER BY purchase_datetime;
```

Само отсутствие даты в таблице не доказывает сбой: сопоставляйте его с журналом загрузки и ответом источника.

## SQL и инфраструктура

В [каталоге SQL](../sql/README.md) каждый файл — самостоятельный SELECT с CTE. Выберите нужную базу в DBeaver или Metabase и запускайте запросы по одному. Запросы не создают постоянные витрины и не сохраняют результаты автоматически.

Пример расписания cron опубликован в [`deployment/cron.example`](../deployment/cron.example). Docker-конфигурация и параметры рабочего подключения Metabase не публикуются; для воспроизведения достаточно развернуть PostgreSQL, создать таблицу, загрузить данные и подключить Metabase к этой базе.
