## Аналитические кейсы — 06.10.2026

- Добавлены два исследования в Markdown с переходами от результатов к бизнес-рекомендациям и дизайну проверки эффекта.
- Опубликованы две презентации PPTX и два отчёта DOCX из подготовленного комплекта. Их числовые результаты сохранены без нового пересчёта базы.
- Добавлены исторический снимок агрегатов с именованными полями, CSV, три графика и скрипт их построения из JSON.
- README перестроен вокруг бизнес-вопросов, ключевых результатов и ссылок на исследования, отчёты и SQL. Снимки Metabase собраны на отдельной странице.

Графики и CSV воспроизводятся без API и PostgreSQL. Публикация не подтверждает новый расчёт эмпирических результатов и не включает рабочие параметры подключения.

## Выполненные изменения

- Удалены встроенные реквизиты PostgreSQL из исторического загрузчика; оба скрипта используют обязательные переменные окружения. Адрес рабочего сервера и исходный пароль в репозиторий не включены.
- Добавлен `requests` в зависимости. `os` и `datetime` относятся к стандартной библиотеке; `psycopg2.extras` устанавливается вместе с `psycopg2-binary`.
- SQL разделён на самостоятельные запросы. Добавлены недостающие завершающие `;`, заголовки и каталог. Промежуточные и итоговые варианты сохранены и подписаны.
- В первые пять ABC-запросов добавлен фильтр 2023 года: в исходнике эти запросы читали все даты. Это согласует период с XYZ и защищает годовой анализ от новых ежедневных загрузок.
- В первом ABC-запросе добавлен `product_id` к сортировке оконной суммы для однозначного порядка товаров с равной выручкой.
- Добавлены `.gitignore`, `.env.example`, README и описание методологии и запуска.

Загрузчики не переписывались в новый ETL-фреймворк. Формулы, RFM-пороги, XYZ-пороги и критерии CCZ сохранены. Возможные изменения поведения на расширенном наборе данных, включая нулевую активность когорт, описаны в методологии.

## Проверки и границы

Локально проверяются синтаксис Python без запуска main, сохранность запросов при разделении и отсутствие исходных реквизитов в подготовленных файлах. Подключение к рабочей базе, HTTP-запросы и историческая перезагрузка при оформлении не выполняются. Проверка SQL на рабочей PostgreSQL и воспроизведение итоговых чисел остаются отдельным этапом.
